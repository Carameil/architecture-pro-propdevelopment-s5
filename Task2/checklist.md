# Проверочный лист безопасности бизнес‑систем PropDevelopment (Task2)

Легенда статусов: Да / Нет / НД (нет данных).

## Обоснование выбора разделов

Исходя из описанных проблем и приоритетов компании:
- Нарушен контроль данных и отсутствуют системные ограничения доступа между ИТ‑продуктами → приоритет разделов «Идентификация и доступ», «Безопасность данных», «Многотенантность/авторизация на уровне объектов».
- Проблемы с API партнёров (избыточные категории данных, сквозной доступ) → приоритет «Интеграции и API безопасность» (аутентификация, авторизация, минимизация данных, шлюз/политики).
- Необходимость масштабирования обработки данных (DWH, BI/ML/AI) при соблюдении законодательства → приоритет «Соответствие требованиям (152‑ФЗ/GDPR/PCI)», «Data Governance», «Анонимизация/псевдонимизация».
- Бóльшая часть сервисов в Kubernetes → приоритет «Kubernetes/контейнерная безопасность» (RBAC, NetworkPolicy, Secret‑ы, аудит).
- Требование оперативно реагировать на инциденты → приоритет «Мониторинг и реагирование на инциденты (SIEM, audit)».
- Базовая инфраструктурная гигиена и восстановление → «Сеть и периметр», «Резервное копирование и восстановление».
